# Nassi RS

Мессенджер для локальной сети без сервера, на Rust (egui). Сделан по мотивам
Network Assistant 4.5 (Gracebyte Software): интерфейс и иконки как в оригинале,
но протокол свой (clean-room, без дизассемблирования), поэтому **со старым Nassi по сети не совместим**.

## Что есть

- **Пользователи**: список всех, кто в сети: состояние, компьютер, IP, время в состоянии, бездействие, пинг,
  активное окно, ОС, аптайм. Есть сортировка по колонкам и группы пользователей. Колонки настраиваются.
  Поиск (поле справа в заголовке, Ctrl+F) — по нику, компьютеру, IP, имени, отделу, состоянию.
- **Общий чат**: чат для всех, с историей на диске. Поддерживает смайлы (пакеты `.asl` из папки
  `Emoticons`, анимированные GIF) и команды `/me`, `/nick`, `/here`, `/m`, `/s`, `/i`, `/help`.
  Поиск по сообщениям — лупа справа вверху (Ctrl+F): совпадения подсвечиваются, ▲/▼ (Enter/Shift+Enter)
  переходят между ними, можно показать только найденные.
- **Личные сообщения**: отдельная вкладка в стиле Telegram — слева список диалогов (аватар, время,
  последнее сообщение, счётчик непрочитанных, «печатает…»), сверху поиск по собеседникам и по тексту
  всей личной переписки; справа выбранный диалог со своим поиском (лупа). ПКМ по пользователю →
  «Написать личное сообщение» открывает эту вкладку с нужным собеседником. Переписка хранится на диске
  (`%APPDATA%\NassiRS\Chats\<uid>.jsonl`). Доставка подтверждается (✔). Если собеседник не в сети,
  сообщение ждёт (⏳) и уходит автоматически, когда он появится.
- **Групповой чат (беседы)**: любой пользователь может создать беседу («Новая беседа» или ПКМ по
  пользователю → «Пригласить в беседу») и добавить в неё людей из списка. Сообщения получают только
  участники: каждому они отправляются отдельно, с подтверждением доставки и дозагрузкой для тех, кто был
  не в сети. Создатель (★) может исключать участников, любой участник может переименовать беседу или выйти.
  История хранится в `%APPDATA%\NassiRS\Groups\`. В беседе тоже есть поиск по сообщениям (лупа).
- **Удалённый доступ** (как Radmin Viewer): ПКМ по пользователю → «Удалённый доступ».
  - Управление и просмотр рабочего стола. Передаются только изменившиеся участки экрана (JPEG).
    Можно выбрать монитор, качество и частоту кадров; есть режим «во весь экран»,
    кнопки Win, Alt+Tab, Ctrl+Shift+Esc, Win+R и передача буфера обмена.
  - Командная строка: команда выполняется на удалённом ПК, вывод возвращается.
  - Питание: заблокировать, выйти из системы, перезагрузить, выключить.
  - Передача файлов.
- **Журнал событий**: кто пришёл/ушёл, файлы, удалённые запросы, ошибки сети.
- Состояния (Готов / Работаю / Не беспокоить / Приватный / Отошёл / Не в сети и до 6 своих),
  автоответ, автоматический переход в «Отошёл» при бездействии.
- Сигналы, передача файлов с докачкой, «Мои данные» с фото.
- Информация о пользователе: данные, процессы, снимок экрана, буфер обмена. Всё это по умолчанию
  **запрещено** (Настройка → Приватность), и каждый запрос пишется в Event Log у того, к кому обращались.
- Трей, всплывающие уведомления, звуки из папки `Sounds`.
- **Мигание при новом сообщении**: если вас нет на месте (окно не активно, свёрнуто в трей или
  нет действий с мышью/клавиатурой дольше заданного времени) и пришло сообщение — в общем чате, личное
  или в беседе — мигает кнопка программы в панели задач, а в трее значок с красной точкой. Мигание
  прекращается, когда вы вернётесь к окну. Включается в Настройка → Общие.
- **Приватность**: в состоянии «Приватный» (Ctrl+P) другие не видят ваше активное окно (в списке
  у них «—»), процессы, экран и буфер обмена. В Настройка → Приватность можно включить те же
  ограничения для всех состояний; там же видно, что другие видят прямо сейчас.
- Клавиши как в оригинале: Ctrl+R/W/D/P/A/O, F4, F5, Alt+F1/F2/F3/F5, Alt+F6 (личные сообщения),
  Alt+1…5 (вкладки), Ctrl+F (поиск), Alt+S, Alt+M, Esc, Ctrl+↑/↓, Tab, Alt+R (исправление раскладки),
  Shift+F1..F12 (макросы).

## Сеть 20011972

- Один порт: **50240**, один и тот же для UDP и TCP. Настраивать ничего не нужно.
- Всё, что адресовано всем, уходит broadcast'ом на **255.255.255.255:50240**. Личные сообщения идут
  unicast на `IP:50240`, файлы и снимки экрана — по TCP на тот же порт.
- **Интерфейс закрепляется жёстко.** При первом запуске выбирается физическая сетевая карта
  (VPN, виртуальные адаптеры и 169.254.x пропускаются), и её IP записывается в настройки.
  Сам он больше не меняется. Если адаптера нет, программа слушает на всех интерфейсах и пишет
  предупреждение в Event Log, но настройку не трогает. Сменить интерфейс: Настройка → Соединение.
  Оригинальный Nassi в этой сети цеплялся к VPN-интерфейсу `happ-xray` (172.19.0.1).
- Настройки пишутся атомарно, с резервной копией `config.json.bak`. Если файл повреждён,
  они восстанавливаются из копии, а не сбрасываются.
- Необязательный «сетевой пароль» шифрует трафик (ChaCha20-Poly1305). Общаться могут только копии
  с одинаковым паролем.

## Удалённый доступ

Удалённый доступ всегда включён и защищён **встроенным паролем администратора**. Пароль задан
в программе, из настроек его поменять нельзя. В exe хранится только его хэш (`ADMIN_KEY_HEX` в `src/proto.rs`).
Чтобы сменить пароль, нужно пересчитать хэш, пересобрать программу и обновить её на всех ПК.

Пароль спрашивается при **каждом** действии: при подключении (управление или просмотр), при каждой команде
командной строки и при каждой команде питания. Компьютер сотрудника проверяет его каждый раз заново
по схеме challenge-response, так что сам пароль по сети не передаётся. После неверного пароля
следует задержка 2 с, а попытка записывается в Event Log.

Во время сеанса на управляемом ПК сверху всегда виден красный индикатор «Вашим ПК управляет…»
с кнопкой «Отключить». Каждое подключение, команда и действие с питанием записываются в Event Log.

Ограничения Windows:
- Без прав администратора программа не может управлять окнами, запущенными «от имени администратора».
- Запрос UAC, экран блокировки и Ctrl+Alt+Del программе недоступны вовсе (для этого нужна служба Windows).
  Чтобы управлять окнами администратора, запускайте NassiRS на ПК сотрудника от имени администратора.

## Установщик (x86 + x64, Windows 7 SP1 … 11)

```
powershell -ExecutionPolicy Bypass -File installer\build-installer.ps1
```

Скрипт собирает три варианта программы (`target\dist\...`) и создаёт один установщик
`dist\NassiRS-Setup-<версия>.exe` (Inno Setup 6, `installer\nassi-rs.iss`):

| Система | Сборка |
|---|---|
| 64-битная Windows 10/11 | `x86_64-pc-windows-msvc` (stable) |
| 64-битная Windows 7 SP1 / 8 / 8.1 | `x86_64-win7-windows-msvc` (nightly) |
| 32-битная Windows 7 SP1 … 11 | `i686-win7-windows-msvc` (nightly) |

Обычные цели Rust (`*-pc-windows-msvc`) поддерживают только Windows 10 и новее, поэтому для Windows 7/8.1
и для 32-битных систем используются цели `*-win7-windows-msvc`. Это цели третьего уровня: стандартная
библиотека для них собирается из исходников (`cargo +nightly build -Zbuild-std`), скрипт сам ставит
nightly-набор с `rust-src`. Установщик 32-битный и запускается на любой из этих систем (минимум —
Windows 7 SP1), сам выбирает подходящую сборку и ставит её для текущего пользователя всегда в одну и ту же
папку `%LOCALAPPDATA%\Programs\Nassi RS` (выбора папки нет, каждое обновление заменяет программу на месте), и
**права администратора не нужны**. Вместе с программой ставятся папки `Emoticons`
и `Sounds`. При установке можно отметить:
- ярлык на рабочем столе;
- автозапуск при входе в Windows;
- правило брандмауэра для частной и доменной сети — единственный пункт, которому нужны права
  администратора: он выключен по умолчанию, и Windows спросит их (UAC) только если его отметить.

Если раньше программа была установлена для всех пользователей (в `Program Files`), установщик
предложит удалить эту старую копию (Windows один раз спросит права администратора). Иначе при входе
в Windows будут запускаться обе. Настройки и переписка в `%APPDATA%\NassiRS` при этом сохраняются.
При удалении убирается и правило брандмауэра (если оно ставилось); переписка в `%APPDATA%\NassiRS` остаётся.
Среда выполнения C встроена статически, поэтому Visual C++ Redistributable не нужен.
Окно по умолчанию рисуется **программно** — процессором, без видеокарты и драйвера OpenGL:
на офисных ПК (встроенная графика Intel на Windows 7, например Pentium G2020) драйвер OpenGL рисует окно
с артефактами — растянутые треугольники и полосы текста на тёмном фоне. Настройка → Общие → «Отрисовка окна»:
- «Программная (без видеокарты)» — по умолчанию; при обновлении со старых версий режим «Автоматически»
  тоже переключается на программную;
- «OpenGL (видеокарта)» — всегда OpenGL;
- «Автоматически» — OpenGL, если драйвер поддерживает OpenGL 3.0+ и прошёл самопроверку (тестовый кадр
  сравнивается с программной отрисовкой; неудача запоминается в `opengl-broken.txt` в папке данных),
  иначе программная. Встроенная графика Intel на Windows 7/8.x и драйверы Intel с OpenGL ниже 3.3 сразу
  рисуются программно. Если OpenGL не запустился, программа перезапускается с программной отрисовкой.

### Автообновление

Программа обновляется сама из общей папки (по умолчанию `\\server\hole\update`, меняется в
Настройка → Обновление). При запуске и затем раз в час она ищет там файл `NassiRS-Setup-<версия>.exe`
с версией новее своей. Найденный файл копируется в `%TEMP%\NassiRS-update` и устанавливается тихо, без
вопросов и без прав администратора. После установки программа запускается снова (если была в трее, то в трее).
Пока идёт передача файла или удалённый сеанс, обновление ждёт. Во время работы оно ждёт ещё и момента,
когда окно программы не используется. Если установка не удалась, следующая попытка будет через сутки
(или по кнопке «Проверить сейчас»).

Выпуск новой версии:
1. поднять `version` в `Cargo.toml` (например, `0.2.3` → `0.2.4`);
2. `installer\build-installer.ps1 -Publish`: соберёт установщик и положит его в `\\server\hole\update`
   (другая папка: `-UpdateDir \\srv\share`).

Старые установщики из папки можно не удалять: берётся самый новый.

Какой режим выбран и почему — видно в «Журнале событий» (источник «Отрисовка») и в настройках.
На один запуск режим можно задать ключом: `--opengl` (ярлык «Nassi RS (OpenGL)») или `--software`.

Установщик можно собрать и на Linux (mingw-w64 + NSIS, сборки `*-win7-windows-gnu`):
`installer/build-installer.sh` → `dist/NassiRS-Setup-<версия>.exe` (`installer/nassi-rs.nsi`).
Тихая установка такого установщика: `NassiRS-Setup-0.2.3.exe /S`.

Тихая установка (например, через групповую политику или скрипт):
`NassiRS-Setup-0.2.3.exe /VERYSILENT /SUPPRESSMSGBOXES /TASKS="autostart,firewall"`

## Запуск

```
cargo build --release
target\release\nassi-rs.exe
```

Смайлы и звуки лежат в проекте, в папках `Emoticons\` и `Sounds\`. Программа ищет их рядом со своим exe
и в родительских папках, поэтому при запуске из `target\…` она находит их в корне проекта,
а после установки — в папке программы. Другой путь можно задать в Настройка → Ресурсы.

Параметры командной строки:

- `--profile ИМЯ`: отдельный профиль (настройки и история), например чтобы запустить две копии на одном ПК.
  Программа запускается только один раз на каждый профиль: повторный запуск (ярлык, меню «Пуск»)
  не открывает вторую копию, а показывает уже работающее окно, даже если оно свёрнуто в трей.
- `--pos X,Y`: позиция окна.
- `--software` / `--opengl`: программная отрисовка или OpenGL на этот запуск (поверх настройки «Отрисовка окна»; по умолчанию программная).

Данные хранятся в `%APPDATA%\NassiRS\` (у профилей — в `profiles\ИМЯ\`).

## Тест сети

`cargo run --release --example probe -- [uid_hex]` показывает, кто отвечает в сети, и отправляет
пользователю с указанным uid личное сообщение, а затем ждёт подтверждения доставки.
